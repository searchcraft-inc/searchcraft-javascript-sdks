# AGENTS.md — Searchcraft JavaScript SDKs

This file provides guidance for AI agents working in this repository.

---

## Project Overview

This is a **Yarn workspaces monorepo** containing the Searchcraft JavaScript SDKs — a suite of front-end packages that provide search UI components and business logic for consuming applications of the [Searchcraft](https://searchcraft.io) search engine.

---

## Package Structure

| Package | Name | Description |
|---|---|---|
| `packages/javascript-sdk` | `@searchcraft/javascript-sdk` | **Core package.** Stencil web components + `SearchcraftCore` class. Source of truth for all UI components. |
| `packages/react-sdk` | `@searchcraft/react-sdk` | React wrappers auto-generated from the Stencil output targets. Do not edit `src/stencil-output/` by hand. |
| `packages/vue-sdk` | `@searchcraft/vue-sdk` | Vue wrappers auto-generated from the Stencil output targets. Do not edit `src/stencil-web-components.ts` by hand. |
| `packages/hologram` | `@searchcraft/hologram` | SCSS design-system / theme source. Built first; output is consumed by `javascript-sdk`. |
| `packages/compendium` | `compendium` | Storybook stories (React + Vue) and a Next.js demo app. Private package — not published. |

### Build dependency order (enforced by `build.mjs`)

```text
hologram → javascript-sdk → react-sdk / vue-sdk
```

## Key Technologies

- **Yarn Classic** (workspaces) — package manager and workspace orchestration
- **Stencil** — web-component compiler; produces the `javascript-sdk` dist and auto-generates React/Vue proxies
- **TypeScript** — strict mode, `es2022` target, `Bundler` module resolution
- **Biome** — linter + formatter (replaces ESLint/Prettier)
- **Vite + vitest** — build + test for React/Vue SDKs
- **Lerna** — versioning and changelogs
- **Storybook** — component development / visual testing (via `compendium`)
- **typedoc** — API documentation generation

## Architecture Notes

### `javascript-sdk` is the single source of truth for UI

- All Stencil components live in `packages/javascript-sdk/src/components/`.
- The Stencil build auto-generates `packages/react-sdk/src/stencil-output/` and `packages/vue-sdk/src/stencil-web-components.ts`. **Never edit those files manually.**
- The `SearchcraftCore` class (`src/classes/SearchcraftCore.ts`) is the central business-logic entry point; it manages state via a Zustand store, initialises search/measure/ad clients, and emits subscription events.

### Component `readme.mdx` files are auto-generated

- Files at `packages/javascript-sdk/src/components/<name>/readme.mdx` are generated by the Stencil `docs-custom` output target in `stencil.config.ts`. Do not edit them manually.

### Hologram (SCSS theme) must be built before `javascript-sdk`

- `packages/hologram/src/` contains the design-system SCSS. The compiled CSS is embedded in the `javascript-sdk` build. Always rebuild hologram when changing styles.

### TypeScript path aliases (inside `javascript-sdk`)

- `@clients` → `src/clients/`
- `@types` → `src/types/`
- `@store` → `src/store/`
- `@utils` → `src/utils/`

### `searchcraftId` and `CoreInstanceRegistry`

- Every Stencil component has a `searchcraftId?: string` prop that links it to a `Searchcraft` instance.
- The default ID is `'searchcraft'` (`DEFAULT_CORE_INSTANCE_ID`). Omitting the prop uses this default.
- Multiple `Searchcraft` instances on one page require unique IDs passed consistently to both the class constructor and every component.
- Components locate their instance through the singleton `registry` (`CoreInstanceRegistry`), not via direct imports of `SearchcraftCore`.

### Stencil component lifecycle pattern

All components that need store access follow this exact pattern — do not deviate from it:

```ts
connectedCallback() {
  this.cleanupCore = registry.useCoreInstance(
    this.searchcraftId,
    this.onCoreAvailable.bind(this),
  );
}

disconnectedCallback() {
  this.unsubscribe?.();   // unsubscribe from Zustand store
  this.cleanupCore?.();   // unregister from CoreInstanceRegistry
}
```

`registry.useCoreInstance()` returns a cleanup function and calls `onCoreAvailable` immediately if the instance already exists, or defers until it's registered.

### React SDK: dual client / server builds

`react-sdk` has two separate entry points built by two Vite configs:

| Entry | Output | Purpose |
| --- | --- | --- |
| `src/client/index.ts` | `dist/client/` | Browser components — thin wrappers over Stencil output |
| `src/server/index.ts` | `dist/server/` | React Server Components — use `renderToString` from the hydrate package |

When adding a new component to `react-sdk`, **both** a client wrapper (`src/client/`) and a server wrapper (`src/server/`) are required. `react` and `react-dom` are peer dependencies and are externalized from both builds.

### Public API surface (`src/index.ts`)

- The consumer-facing class is `Searchcraft` (extends `SearchcraftCore`). `SearchcraftCore` is also exported for use by other SDKs.
- **Do NOT export components from `src/index.ts`** — components register themselves as custom elements; they are not imported directly.
- Only types (`SearchcraftConfig`, `Components`, `JSX`, `@types` barrel) and classes belong in this file.

### Auto-generated and post-processed files — never hand-edit

The following files are written or patched automatically during the build and must not be edited manually:

| File | Generated by |
| --- | --- |
| `packages/react-sdk/src/stencil-output/components.ts` | Stencil `reactOutputTarget` |
| `packages/vue-sdk/src/stencil-web-components.ts` | Stencil `vueOutputTarget` + `post-build.js` |
| `packages/javascript-sdk/src/components.d.ts` | Stencil compiler + `post-build.js` |
| `packages/javascript-sdk/dist/components/defineCustomElements.js` | `post-build.js` |
| `packages/javascript-sdk/src/components/*/readme.mdx` | Stencil `docs-custom` target |

`post-build.js` also appends `?scv=<version>` query strings to all dist JS imports for cache busting. Do not use `?v=` — it conflicts with Vite's internal module cache.

## Code Style

### Formatting & Linting (Biome)

- **Indent**: 2 spaces
- **Line width**: 80 characters
- **Quotes**: single quotes for JS/JSX
- **Semicolons**: always
- **Import organisation**: auto-sorted by Biome
- Ignored paths: `**/dist/**`, `**/node_modules/**`, `src/components.d.ts`, `src/themes/hologram.css`, `src/stencil-output/*`, `src/stencil-web-components.ts`

Always run `yarn lint:fix` before committing.

### TypeScript

The root `tsconfig.json` applies to the whole monorepo with strict settings. Key rules to be aware of when writing code:

- **`strict: true`** — all strict checks enabled; avoid `any` casts.
- **`noUnusedLocals` / `noUnusedParameters`** — unused variables and parameters are compile errors; use `_` prefix to intentionally ignore a parameter.
- **`noUncheckedIndexedAccess`** — array/object index access returns `T | undefined`; always narrow before use.
- **`verbatimModuleSyntax`** — use `import type` for type-only imports; don't mix value and type imports in the same statement.
- **`noImplicitAny: false`** — implicit `any` is permitted but should be avoided in new code.
- Target is **`es2022`** with **`Bundler`** module resolution — use ESM syntax throughout; no CommonJS `require`.

### Naming Conventions

- **Classes**: `PascalCase` (e.g. `SearchcraftCore`, `MeasureClient`)
- **Stencil components**: kebab-case tag names prefixed with `searchcraft-` (e.g. `searchcraft-input-form`)
- **Files**: match the primary export — `SearchcraftCore.ts`, `searchcraft-input-form.tsx`
- **Test files**: `.spec.ts` suffix, co-located with the file under test

### JSDoc

- All public-facing classes, methods, and `@Prop` declarations must have JSDoc comments.
- Use `@deprecated` with a migration note for anything being phased out.
- Use the `@internal` JSDoc tag on Stencil components or props to exclude them from generated `readme.mdx` docs.

## Testing Guidelines

- Unit/spec tests use `.spec.ts` suffix and live alongside the source file they test.
- `javascript-sdk` tests run via Stencil (`stencil test --spec --e2e`).
- `react-sdk` and `vue-sdk` tests run via **vitest**.
- Do not create test files outside the package they belong to.
